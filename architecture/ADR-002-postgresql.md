# ADR-002: PostgreSQL для постоянных данных

- Статус: принято
- Дата: 10.10.2026

## Контекст

Приложение хранит пользователей, их профили и настройки, рецепты, оценки и события использования. Между данными нужны внешние ключи, уникальность адреса и оценки, а удаление пользователя должно убирать связанные записи. Списки продуктов, ингредиентов, шагов, предпочтений и исключений должны сохранять порядок и обновляться без хранения массивов в JSON.

## Решение

Для запуска приложения использовать PostgreSQL 17 через Docker Compose и менять схему миграциями Alembic. Таблицы данных приведены к 3НФ; порядок значений списков хранится в дочерних таблицах. SQLite разрешён для быстрых изолированных тестов. Проверки PostgreSQL выполняются в CI на PostgreSQL 17.

## Рассмотренные варианты

- **SQLite как единственная БД:** проще развернуть, но хуже подходит для одновременной работы нескольких экземпляров приложения и целевого контейнерного запуска.
- **Документная БД:** не даёт преимуществ для связей и ограничений между пользователем, рецептом и оценкой.

## Последствия

Одна реляционная схема обеспечивает ограничения и каскадное удаление; миграция переносит данные из прежних JSON-списков с сохранением порядка. PostgreSQL требует отдельного контейнера и настройки подключения; запуск БД и приложения описан в Compose. Репликация, кэш и шардинг не нужны для ожидаемой нагрузки.
