# ADR-002: PostgreSQL для постоянных данных

## Контекст

Модель данных содержит связанные сущности: пользователей, профили, рецепты и оценки. Для них важны внешние ключи, уникальные значения, каскадное удаление и сохранение порядка ингредиентов и шагов.

## Решение

Для постоянного хранения использовать PostgreSQL. Версия 17 закреплена в Docker Compose и CI для воспроизводимого запуска. Схема изменяется миграциями Alembic; связанные списки хранятся в отдельных таблицах. SQLite используется для быстрых изолированных тестов, а интеграционные проверки базы запускаются на PostgreSQL.

## Рассмотренные варианты

- **SQLite для постоянного хранения:** проще запустить, но выбранная схема и целевое окружение уже проверяются на PostgreSQL.
- **Документная БД:** не даёт нужного преимущества для связей и ограничений между сущностями.

## Последствия

Реляционная схема позволяет задавать ограничения и каскадное удаление. PostgreSQL запускается отдельным контейнером; параметры подключения задаются конфигурацией приложения. Поведение, зависящее от конкретной СУБД, проверяется интеграционными тестами на PostgreSQL.
