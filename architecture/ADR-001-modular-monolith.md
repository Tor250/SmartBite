# ADR-001: модульный монолит

## Контекст

Основной сценарий включает форму запроса, генерацию рецепта и серверную проверку. Для текущего состава продукта не нужны независимые выпуски частей системы или отдельное масштабирование компонентов.

## Решение

Использовать модульный монолит: один backend-процесс и один выпуск, с отдельными модулями для HTTP API, прикладного сценария, проверки безопасности, генератора и доступа к данным.

## Рассмотренные варианты

- **Микросервисы:** не выбраны. Для независимых выпусков и масштабирования компонентов нет подтверждённой потребности; при этом появятся сетевые взаимодействия, раздельное развёртывание и дополнительный мониторинг.
- **Монолит без модульных границ:** проще в начале, но сложнее заменить генератор или добавить Telegram-клиент без смешивания интерфейса, правил и хранения.

## Последствия

Правила и сценарии можно вызывать из веб-, консольного или Telegram-адаптера. Для запуска приложения достаточно одного backend. Компоненты не масштабируются независимо; решение можно пересмотреть при появлении соответствующего требования.
