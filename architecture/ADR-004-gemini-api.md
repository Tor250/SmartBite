# ADR-004: внешний генератор рецептов

## Контекст

Генератор должен возвращать рецепт в общем JSON-формате: название, ингредиенты, количества и шаги. Приложению нужны ограниченное время ожидания ответа, проверяемая структура результата и возможность сменить поставщика без переписывания прикладной логики.

## Решение

Использовать Gemini Developer API через HTTPS и REST. Базовая модель задаётся конфигурацией `SMARTBITE_GEMINI_MODEL`; в текущей конфигурации указано `gemini-3.5-flash-lite`. Адаптер реализует общий интерфейс `RecipeJsonClient`, запрашивает ответ по JSON Schema и передаёт результат серверному разборщику и проверкам.

Выбор модели является исходной настройкой интеграции, а не утверждением о её превосходстве по качеству рецептов. Для сравнения можно подключить Qwen через существующий адаптер и проверить оба варианта на одинаковых запросах.

## Рассмотренные варианты

- **Gemini Developer API:** выбран для текущей интеграции; официальный API поддерживает структурированный ответ по ограниченному подмножеству JSON Schema. Это соответствует формату рецепта и позволяет проверять структуру до использования результата.
- **Gemini 3.8 Flash:** возможный вариант, если сравнительная проверка покажет, что для качества рецептов нужен более мощный вариант Gemini. Документация описывает его как более сильную модель семейства Flash; это не подтверждает качество именно кулинарных ответов.
- **Qwen через Alibaba Cloud Model Studio:** оставлен как вариант для сравнительной проверки. В документации режим JSON Schema указан для отдельных моделей Qwen Plus; для Qwen Flash описан режим JSON Object. В любом случае серверная проверка результата обязательна.
- **Текстовый ответ без режима структурированного вывода:** не выбран, поскольку увеличивает вероятность постороннего текста и ошибок разбора.

## Настройки и обработка данных

Ключ хранится в `GEMINI_API_KEY`; модель можно переопределить через `SMARTBITE_GEMINI_MODEL`. Ключ доступен только backend и не записывается в журналы. Внешнему генератору передаются список продуктов и общая инструкция; пищевые исключения профиля остаются в backend и проверяются после генерации.

Тайм-аут HTTP-вызова составляет 25 секунд, общий предел ожидания — 30 секунд. При сетевой ошибке, пустом или некорректном ответе рецепт не показывается. Структурированный ответ не гарантирует правильность рецепта: сервер разбирает его по общей схеме и проверяет ингредиенты до показа.

Перед передачей реальных пользовательских данных необходимо сверить действующие условия хранения и обработки данных выбранного тарифа API. По условиям Google неоплачиваемый доступ может использовать отправленные данные для улучшения сервисов; платный доступ имеет другие условия обработки. Условия описаны в [дополнительных условиях Gemini API](https://ai.google.dev/gemini-api/terms).

Те же условия запрещают использовать Gemini API для предоставления медицинских рекомендаций или в клинической практике. Поэтому применимость Gemini нужно отдельно оценивать для каждой функции SmartBite, связанной с питанием при диагнозах. Для таких функций нельзя считать выбранного поставщика допустимым без проверки его условий и границ продукта.

## Последствия

Интеграция с поставщиком изолирована в адаптере; смена модели не требует менять контракт рецепта или проверки. Качество моделей следует сравнивать на одном наборе запросов по пригодности рецепта, соответствию запросу, соблюдению JSON-схемы, времени ответа и стоимости. Само наличие структурированного вывода не заменяет эти проверки.

Источники: [структурированный вывод Gemini](https://ai.google.dev/gemini-api/docs/structured-output), [структурированный вывод Qwen](https://help.aliyun.com/en/model-studio/qwen-structured-output).
