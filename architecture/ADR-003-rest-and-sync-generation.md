# ADR-003: REST и синхронный вызов генератора

- Статус: принято
- Дата: 10.10.2026

## Контекст

Основной клиент — браузер; позже может появиться Telegram-адаптер. Внутренних самостоятельных сервисов пока нет. Генерация — один запрос с одним ответом, а добавление очереди потребовало бы хранить задания, отслеживать состояния и решать переполнение и повторную доставку.

## Решение

Использовать REST с JSON и спецификацией OpenAPI для клиентского API. Gemini Developer API вызывается из адаптера через HTTPS; общий интерфейс `RecipeJsonClient` сохраняет возможность замены поставщика. Синхронный вызов генератора выполняется в отдельном пуле потоков: одновременно допускаются не более четырёх запросов, остальные сразу получают ответ о временной перегрузке. Ожидание ответа ограничено 30 секундами, сетевой тайм-аут Gemini — 25 секунд. Очередь в MVP не вводить. Ответ генератора не показывать до проверки ингредиентов.

## Рассмотренные варианты

- **gRPC между внутренними сервисами:** сейчас нет внутренних сетевых сервисов; браузер напрямую работает с REST, а вызовы модулей backend остаются локальными.
- **Очередь сообщений:** позволила бы отделить длительную генерацию, но требует брокера, мониторинга очереди и решений для переполнения; для учебного MVP эта стоимость не оправдана.

## Последствия

REST-запросы доступны браузеру и легко проверяются через OpenAPI и curl. Gemini не связан с доменной логикой: адаптер переводит запрос и ответ в общий JSON-контракт рецепта. Backend ограничивает число одновременных вызовов и время ожидания, возвращает понятную ошибку при перегрузке, тайм-ауте или сбое и не показывает непроверенный черновик. Если фактическое время генерации или нагрузка вырастут, очередь можно оценить отдельным ADR.
