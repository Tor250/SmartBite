# ADR-003: REST и синхронный вызов генератора

## Контекст

Основной клиент — браузер; позже может появиться Telegram-адаптер. Внутренних самостоятельных сервисов пока нет. Генерация — один запрос с одним ответом, а добавление очереди потребовало бы хранить задания, отслеживать состояния и решать переполнение и повторную доставку.

## Решение

Для клиентского API использовать REST с JSON и спецификацией OpenAPI. Внешний генератор вызывается из адаптера через HTTPS; интерфейс `RecipeJsonClient` позволяет заменить поставщика без изменения прикладного сценария. Синхронный вызов выполняется в отдельном пуле потоков: одновременно допускаются не более четырёх запросов, остальные получают ответ о временной перегрузке. Ожидание ответа ограничено 30 секундами, сетевой тайм-аут — 25 секунд. Очередь не вводить. Ответ генератора не показывать до проверки ингредиентов.

## Рассмотренные варианты

- **gRPC между внутренними сервисами:** сейчас нет внутренних сетевых сервисов; браузер напрямую работает с REST, а вызовы модулей backend остаются локальными.
- **Очередь сообщений:** позволила бы отделить длительную генерацию, но требует брокера, мониторинга очереди и правил обработки переполнения; при текущем сценарии такая сложность не оправдана.

## Последствия

REST-запросы доступны браузерному клиенту и проверяются по OpenAPI. Адаптер переводит запрос и ответ внешнего генератора в общий JSON-контракт рецепта. Backend ограничивает число одновременных вызовов и время ожидания, возвращает ошибку при перегрузке, тайм-ауте или сбое и не показывает непроверенный результат. При изменении нагрузки необходимость очереди можно оценить отдельно.
